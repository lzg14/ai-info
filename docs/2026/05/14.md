AI 正在重塑创业公司的构建方式。从来没写过一行代码的创始人，今天已经在交付生产级应用。10 个人的独角兽，从传奇变成了常规操作。

Anthropic 这份 36 页手册重新绘制了创业旅程的四个核心阶段——**想法（Idea）、MVP、启动（Launch）、规模化（Scale）**——并讲清楚每个阶段在 AI 成为核心基础设施时该怎么走。

---

## 一、「创始人」这个角色在变

过去，创始人的定义取决于他们**能做什么**：技术创始人写代码，非技术创始人跑业务。2026 年，「能建东西的人」和「有好想法的人」之间的墙没了。

- 没有工程背景的人，现在可以做出生产级软件
- 有技术背景但缺商业经验的创始人，可以轻松产出 GTM 策略、财务模型和打磨精良的 pitch deck

**AI 带来的最大变化，是解放了有行业经验的非技术创始人。** 创业者不再只从工程背景的人里出来，完全不同背景的人开始创业，去解决传统技术创始人压根没注意到的真实问题。

### AI 帮初创公司像大公司一样运转

| 能力 | 类比 | 具体场景 |
|------|------|----------|
| **对话式智能与研究** | 所有领域随叫随到的专家 | 竞品分析、市场规模测算、财务建模；pitch deck、案例研究、投资人备忘录；魔鬼代言人分析、事前验尸、情景推演 |
| **Agentic Coding** | 永远在线、永远不被阻塞的工程师 | 用自然语言描述需求，AI 去生成、测试、调试和重构代码库 |
| **工作流自动化** | 按需使用的自动运营团队 | CRM 自动更新、周报自动汇总、文档随版本同步 |

### Claude 三个产品形态用法速查

| 任务类型 | 用哪个 | 为什么 |
|----------|--------|--------|
| 快速问答、一次改写、快速头脑风暴 | **Chat** | 快，对话式，无需设置 |
| 研究、分析、从你的文件构建完成文档 | **Claude Cowork** | 文件夹访问、连接器、技能、定时运行 |
| 写代码、测试或交付软件 | **Claude Code** | 代码库访问、diff、git、开发环境 |

## 二、想法阶段（Idea Stage）

**目标**：以研究为导向的验证——投入资源建产品之前，先收集扎实的证据证明真实问题存在，且你的方案真正能解决它。

### 核心问题清单

按这个顺序回答：

1. 这个问题是否真实、具体、频率够高，值得围绕它建产品？
2. 具体谁有这个问题，这算不算一个市场？
3. 有没有别人在解决它，如果有，怎么解决的，解决得好不好？
4. 一个解决方案到底需要做什么才能解决这个问题，我的想法做到了吗？

### 退出条件

想法阶段的退出条件是找到**问题-方案匹配（Problem-Solution Fit）**。当你能对以下三个问题都回答「是」时，才可以离开想法阶段：

- **问题真实且具体**：你能准确说出谁遇到这个问题，多久遇到一次，严重程度如何，他们目前怎么应对
- **方案解决的是实际验证揭示的问题**：不是你最初假设的那个
- **有足够信号支撑构建**：等待确定性本身就是一种失败模式，但需要足够的定性证据让投入 MVP 成为推理决策

### 三个常见坑

**① 把建东西当成验证**

42% 的创业公司死因是建了没人要的东西。Agentic Coding 大幅压缩了从想法到产品的距离，这个失败率只会往上走。

一个能跑的原型很容易被误认为是在解决真实问题的铁证，但它不是。原型的价值在于它是用户访谈的道具——**这些对话本身才是真正的证据**。

**② 过早扩张**

Agentic Coding 助手效率太高，你可以在验证问题-方案匹配之前就把执行大幅推进，而且全程没有意识到自己偏离了航线。它会用完全一样的热情为一个根本错误的前提生成代码库。

**首要原则：让你的判断跑在建设前面。**

**③ 丧失客观性**

让 AI 验证你的创业想法，它会找到支持证据；让 AI 测算市场规模，它会找到那个让 TAM 看起来可融资的数字。解药：用同一个工具，调个方向，让 AI 同样认真地反驳你的想法。

### 想法阶段实践

**压力测试问题假设**
> 和 Claude 一起打磨问题陈述，直到变成可测试的假设。例如「合同审查太慢了」无法测试，但「中型企业法务团队每个合同审查周期花 3 天以上，因为修改意见分散在邮件往来而非版本控制文档中」就非常可测试。

**竞品格局梳理**
> 按层级梳理竞争格局：直接竞品、间接竞品、潜在收购方、可能入场的相邻玩家。然后让 Claude 论证每个层级的真实威胁——不是最容易打发的那个版本。

**客户发现流程**
> 先自己手写访谈问题，让 Claude 审核，标出引导性的、面向未来的、太宽泛的问题。每 5 次访谈之后，让 Claude Cowork 综合笔记，列出支持假设的证据和挑战假设的证据。

## 三、MVP 阶段

**目标**：把验证过的问题转化为真实用户会实际使用的可运行产品，同时不积累会持续恶化的技术债务。

### 核心目标

- 产出关于产品-市场匹配（PMF）的真实证据：用户回来再用、愿意付费、愿意推荐
- 快速推进，同时不给以后挖坑

### 三个常见坑

**① Agentic 技术债务**

速度不是问题，但速度成为唯一变量时，技术债务会积累到还不起。每个 session 都从零开始重新推导基础性决策，代码库最后会没有一个连贯的心智模型。

**解法**：在 Claude Code 写第一行代码之前，先用 Claude 把架构决策定下来，保存为 `CLAUDE.md`，每个 session 都参考它。

**② 被虚假 PMF 骗了**

Agentic Coding 让你更快到达一个"看起来有数字"的时刻，但早期热闹不等于产品-市场匹配。上线那股劲来自临时性力量：创始人朋友圈、投资人介绍、Hacker News 流量。

**③ 范围蔓延**

建东西没有摩擦力且几乎免费的时候，总有一个很酷的功能可以加。每一个单独看都合理，但产品膨胀到超出原始边界时，你会失去方向和势头。

**解法**：开始建之前写一份范围定义文档，描述 MVP 做什么、**刻意不做什么**。

### MVP 阶段实践

**上线前建好衡量框架**
> - **Sean Ellis 测试**：问活跃用户「如果你不能再用这个产品了，你会有什么感觉？」超过 40% 回答「非常失望」，这是有意义的 PMF 指标
> - **努力测试**：PMF 之前，留存需要持续干预；PMF 之后，产品开始自己做这些工作。当事情开始拉着走而不是推着走的时候，这种努力的转变是最清晰的信号

## 四、上线阶段（Launch Stage）

**目标**：把早期引力变成一个可重复的、可持续的增长引擎，同时让基础设施经得住真实生产环境。

### 退出条件

- **增长是可重复的**：通过特定渠道可预测获取用户，CAC、LTV、回本周期是你知道且能辩护的数字
- **产品能承受生产级工作负载**：基础设施加固，安全合规到位
- **运营不依赖创始人**：流程存在了，自动化到位了

### 三个常见坑

**① 技术债务到期**

MVP 阶段积累一些技术债务是速度的合理代价。上线阶段，这些债务开始产生利息，拖得越久修复成本越高。

**② 创始人变成瓶颈**

几个信号：本该一小时做完的决策现在要一周，客服请求堆积因为只有你知道答案。

从「做这些工作」到**「设计做这些工作的系统」**，是创业生命周期中最难的转变之一。

**③ 过早扩张到新市场**

初始引力是真实的，但它也是特定于早期受众的。过早扩张到和原始市场有重大差异的新市场，会引入新的用户行为、合规要求和基准期望。

## 五、规模化阶段（Scale Stage）

**目标**：技术基础设施继续扩展，组织本身也长成一个真正的业务，通过积累的深度建护城河。

### 退出条件

门槛事件（不是单一里程碑）：公司是可持续的，即使创始人越来越多地退出日常运营。实际操作中通常取以下三种形式之一：

- 不再需要外部资本的可持续盈利能力
- IPO 就绪状态
- 被收购

### 规模化挑战

| 挑战 | 说明 |
|------|------|
| **委托运营层** | 从创建系统到让系统成熟到完全可信赖，然后真正信任它们 |
| **扩展技术运营** | 客户不再只评估产品，他们想知道你的组织能不能成为可靠的基础设施合作伙伴 |
| **建 GTM 功能** | 有机增长有天花板，用户增长曲线走平、获客成本上升、管道只在创始人亲自参与时才推进 |

### 规模化阶段实践

**把创始人知识转化为 AI 上下文**
> 找出一个通用竞争对手在你的垂直领域一定会搞错的边界情况，和 Claude Code 一起为它建专门的测试用例。每次类似边界情况出现就加进去——测试套件变成了护城河的地图。

**建工作流锁定**
> 让用户在工作流中使用产品越久，产品就嵌入得越深：他们上面建了自动化，训练了人，连到了数据源和其他工具。到这个程度，换产品就从一个产品决策变成了一个全面的运营工程。

## 核心 Takeaways

1. **想法阶段的验证永远不可跳过**——AI 让构建变快了，但不会让验证变得多余
2. **创始人角色 = 智能体协调员**——从"自己干"到"指挥 AI 干活"
3. **保持判断力领先于构建能力**——尤其当构建毫不费力时
4. **Claude 三件套按场景使用**：Chat 快问快答、Cowork 研究分析、Code 写代码发产品
5. **每个阶段都有独特的失败模式**：提前识别比事后补救便宜得多
